# 日本語の文章

日本語の執筆・編集・レビューには、同梱した `yomiyasu` を使う。  
同梱した指示より、このスキルの適用範囲・制約・出力規則を優先する。

## 実行

1. まず [yomiyasu の指示](vendor/yomiyasu/INSTRUCTIONS.md)を読む。日本語の新規作成・推敲・レビューに適用し、明示的な呼び出しを求める同梱先の条件は適用しない。
2. 指示内の `${CLAUDE_SKILL_DIR}` と相対パスは、このスキルのディレクトリではなく `vendor/yomiyasu/` を基準に解決する。内部文書の `SKILL.md` は、同じ同梱先の `INSTRUCTIONS.md` を指す。
3. 検査には Python 3 と同梱したスクリプトの絶対パスを使い、対象ファイルも絶対パスで渡す。推敲では原文を保存して `run --source` に渡し、新規作成では資料があれば `--material` に渡す。提出前に `verify` を実行する。
4. チャットの文章は一時ファイルで検査する。作業中に作った一時ファイルだけを終了時に削除する。Python 3 を使えない場合は目視で確認し、実行しなかった検査と理由を伝える。

## 優先する制約

同梱した指示を適用するときも、次の制約を守る。

- 事実、数量、条件、例外、不確実さ、時点や順序、義務と推奨の違いを保つ。一部の観察を全体の話に広げない。
- 原因、出典、意見、感情、体験を作らない。具体例が足りなければ、与えられた事実の範囲で書くか、必要な情報を求める。
- URL とコード、コマンド、識別子、パス、引用、製品名は、変更が依頼に含まれない限り、そのまま残す。
- 読み手、文体、形式、長さは依頼に合わせる。同じ意味には同じ語を使う。
- 本文の全角文字と半角英数字の間に半角スペースを入れる。

## 出力

提出前に原文や資料と照合し、意味と技術的な表記が変わっていれば直す。  
推敲では、依頼やこのルールに合わない箇所だけを直す。  
説明を求められなければ、完成した文章だけを返す。同梱先の変更理由や確認の記録は付けない。  
レビューでは、問題箇所、理由、修正案を返す。依頼がなければ全文を書き直さない。  
検査を実行できなかった場合は、その事実と理由を伝える。検査結果を品質の点数として扱わない。
